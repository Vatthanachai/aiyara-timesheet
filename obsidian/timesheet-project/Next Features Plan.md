# Next Features Plan

> Drafted 23 October 2026 on `develop` at `4d8188f`, after backlog items 1–10 and 12–14 of [[Product Backlog]] were merged (item 11, continuous integration, stays deferred by the user). This note lists the features worth building next, in the order to build them, as tasks that a fresh session can pick up without this conversation. Nothing here is started. Update the checkboxes and the dates as work lands.

## How To Resume

1. Read `AGENTS.md` (Git Flow, validation gate, parallel agents) and this note. Pick the first unticked task in the lowest-numbered track.
2. Branch from the latest `develop`: `feature/<short-topic>`. One coherent change per branch.
3. Pipeline per feature (what worked on items 7–14):
   - `backend-implementer` (own worktree) → hand-back with endpoint contract and validation results.
   - A frontend agent (general-purpose, own worktree, `git checkout -B feature/<topic>-ui feature/<topic>` then `git merge develop`) → hand-back.
   - `docs-keeper` → plan note, Project Status top entry (verify it with `grep`, an earlier run claimed an entry that was missing), Product Backlog, Index.
   - `validator` → seven-point gate. Merge only on pass, `--no-ff` into `develop`, resolve docs conflicts by keeping both sides, delete the branch and worktree at once, then deploy the changed services with `scripts/deploy-main.ps1` (rules: no release to `main`, no CI, delete after merge, deploy after merge).
4. Run the mocked Playwright suite (`npx playwright test --workers=2` from `src/Frontend/app`, 132 tests on `develop` at `4d8188f`) only when ports 3100 and 3102–3107 are free: two runs at once collide. Run validators one at a time when they need Playwright.
5. The user pushes: project settings deny `git push` for Claude. Remind them after each merge.

Known facts that save time:

- Identity migrations are linear: the latest on `develop` are `AddTenantRequireMfa` then `AddRefreshSessionDevice`; the Timesheet service's latest is `AddProjectBilling`. Two branches adding a migration to one service: the second merges `develop`, deletes its own migration, regenerates it, reruns tests.
- Gateway forwards `/api/v1/identity/{**}` to Identity, so new Identity routes need no Gateway change. Timesheet and Report routes follow their own existing patterns.
- Frontend: Nuxt Shell in `src/Frontend/app` embeds remotes (`remotes/timesheet`, `reporting`, `administration`, `identity-profile`) in iframes; the Shell relays the session by `postMessage` and every handler checks `event.origin` and `event.source`. Shared helpers are in `src/Frontend/shared` (`api-response.ts`, `i18n.ts`, `date-format.ts`).
- `frame-ancestors` on the timesheet remote is tied to `FRONTEND_ORIGIN`; the Shell must be opened at that exact origin.
- Holidays and a working-days setting already exist (see [[Working Days Plan]]); do not rebuild them. What is missing is listed in track C.

## Track A — Close Known Gaps (build first)

### A1. Billing rate snapshots

Source: not-built list of [[Billable Work And Budgets Plan]]. Today changing a project rate reprices time already logged.

- [ ] Decide and record: store the effective rate per entry at save time (column on `time_entries`) or keep rate history per project with an effective-from date and price entries by their date. Prefer history with effective-from (no backfill of closed months; entries before the first history row use the project's current rate).
- [ ] Timesheet migration (on top of `AddProjectBilling`), API to set a rate with an effective date, usage endpoints price by effective rate.
- [ ] Administration UI: rate history on the project row; usage view unchanged otherwise.
- [ ] Tests: rate change does not reprice earlier entries; closed month stays fixed; cross-tenant isolation.
- Acceptance: changing a rate today leaves last month's usage amounts unchanged.

### A2. Generated by-project and by-client reports

Source: same plan. Usage exists as a screen only.

- [ ] Report service: by-project and by-client report types in the existing generated-report flow (XLSX, CSV, PDF, `report-ready` email), reusing the report snapshot data and the PDF font fixes.
- [ ] Reporting UI entry points beside the existing reports; Thai/English labels.
- [ ] Tests for totals, currency, empty period, and tenant isolation; Smoke step.
- Acceptance: a Tenant Admin downloads a by-client XLSX whose totals equal the usage screen.

### A3. Budget alerts

- [ ] Timesheet: when used hours cross a configurable threshold (default 80% and 100%) of a project's `BudgetHours`, send one email per threshold per project to Tenant Admins (Notification template and internal endpoint, best effort after commit, no duplicates after edits).
- [ ] Administration: threshold setting; show the state on the usage view.
- Acceptance: crossing 80% sends exactly one email; editing entries around the threshold does not resend.

### A4. MFA recovery paths

Source: open points in [[Member MFA Plan]].

- [ ] A sole Tenant Admin who loses the device and recovery codes: add a Platform Admin assisted reset with a reason and an audit row (reuse the existing admin reset), and document the procedure in `docs/developer-runbook.md`.
- [ ] Make an admin reset scoped to the organization instead of clearing the authenticator in every organization the person belongs to, or show a clear warning with the list of affected organizations before confirming.
- [ ] Fix TOTP test flake across the 30 s boundary (compute the code from the server's accepted step like `tests/e2e-real/support/totp.ts`).

### A5. Hardening leftovers from validators

- [ ] Add a test that an Employee token gets 403 from `GET /api/v1/identity/members/audit` (HTTP level and in `tests/phase2/Smoke.ps1`).
- [ ] Add a test for the 429 path of `POST /api/v1/identity/members/invitations/bulk`.
- [ ] `restore-main.ps1`: only restart application containers after a restore that succeeded (or tell the user clearly), refuse files that are not in the manifest, require `globals.sql` and every `<db>.dump` to be listed, and make `-Project` mandatory (no default to the main stack).
- [ ] Add the same `frame-ancestors` middleware to the reporting, administration and identity-profile remotes, keeping `FRONTEND_ORIGIN` the single source.
- [ ] Run the Postgres-backed test mode (`AIYARA_TEST_POSTGRES`) once for the new session, bulk invitation and idempotent-create code, which ran on SQLite only.
- [ ] Look at every new screen by hand on the main stack once: MFA setup and sign-in, Audit log, Signed-in devices, Invite several, offline Timesheet; record what is found.

## Track B — Operations

### B1. Scheduled backups

- [ ] A Windows Task Scheduler or compose-side job that runs `backup-main.ps1` daily, keeps the last N backups, and logs the result; document in the runbook with `-Project aiyara-timesheet` passed explicitly.
- [ ] A periodic restore drill on a test stack (`scripts/test-stack.ps1` plus `restore-main.ps1 -Project <test>`), recorded in [[Backup And Restore Plan]].
- [ ] Back up the secrets that make a restore usable (`PASETO_SIGNING_SEED`, `MFA_ENCRYPTION_KEY`) by a documented manual step; never put them in the repository.

### B2. Alerts on the monitoring that already exists

- [ ] Prometheus/Grafana are in the stack: add alert rules for service down, Gateway 5xx rate, Postgres unavailable, RabbitMQ queue growth, failed report jobs; route to email through the existing Notification service or a documented receiver.

### B3. Continuous integration (deferred)

Deferred by the user until they have used the app themselves (backlog 11). Do not start it unless they say so.

## Track C — Member And Admin Features

### C1. In-app notifications

Today only emails exist. Notification service stores per-user notifications; Shell shows a bell with unread count.

- [ ] Backend: notification table and read/unread API in the Notification service (or Identity-owned inbox, decide by service ownership in [[Services And Projects]]), events for month returned/approved, leave decisions, reminders.
- [ ] UI: bell and list in the Shell header, works with the offline banner, mark read.
- Acceptance: a returned month shows an unread item for that member only.

### C2. Holiday presets and import

Holidays already exist per organization.

- [ ] Import a holiday list from CSV and offer a preset list per country or year to copy into the organization's holidays; no duplicate dates.

### C3. Import entries from CSV and export my data

- [ ] Member CSV import of time entries with the same rules as bulk entry (locked and approved months refused per row, idempotent by a client row id), and a personal data export (entries, leave, profile) as a file.

### C4. Finer roles

- [ ] A read-only reporting role for Tenant members (see reports, change nothing), with tests that every write route refuses it; update [[Security And Tenant Model]].

### C5. Push notifications on mobile

- [ ] Web push for reminders on top of the PWA ([[Mobile And Offline Plan]]); needs a service worker push handler, VAPID keys in secrets, and opt-in per device. iOS needs the app installed to the home screen; record the limits.
